# PL0 课程设计项目看懂指南

这份文档写给自己看，目标是：能看懂项目、能讲清楚项目、答辩时不慌。

项目一句话：

```text
这是一个 PL0 语言扩充版编译器前端演示系统。
它能把一段 PL0 源代码分析成 Token、AST、符号表、语义错误和四元式，并通过网页展示。
```

## 1. 这个项目到底做了什么

课程设计题目是：

```text
PL0 语言扩充
```

本项目实现了这些扩充：

```text
1. 扩充赋值运算：+=、-=
2. 增加自增、自减运算：++、--
3. 增加 for 语句：for <变量> := <表达式> to <表达式> do <语句>
```

整个项目流程：

```text
输入 PL0 源代码
  ↓
Lexer 词法分析
  ↓
Token 序列
  ↓
Parser 语法分析
  ↓
AST 语法树
  ↓
SemanticAnalyzer 语义分析
  ↓
符号表 + 语义错误
  ↓
IntermediateCodeGenerator 中间代码生成
  ↓
四元式
  ↓
Web 页面展示结果
```

用人话讲：

```text
先把代码切成一个个小单词。
再判断这些小单词组合起来是不是合法语法。
再检查变量有没有声明、常量有没有被乱改。
最后把合法程序翻译成比较接近执行步骤的四元式。
```

## 2. 核心概念人话解释

### 2.1 Token 是什么

Token 就是词法分析切出来的一个“小单词”。

比如：

```pl0
x += 1;
```

会被切成：

```text
IDENTIFIER x
PLUS_ASSIGN +=
NUMBER 1
SEMICOLON ;
```

Token 里记录：

```text
类型：它是什么
原文：它长什么样
行号：它在第几行
列号：它从第几列开始
```

对应代码：

```text
Token.java
TokenType.java
Lexer.java
```

### 2.2 AST 是什么

AST 是 Abstract Syntax Tree，抽象语法树。

人话理解：

```text
AST 是程序的结构树。
它不关心代码原来怎么排版，只关心程序由哪些结构组成。
```

比如：

```pl0
begin
  x := 1;
  x += a;
end.
```

AST 里会表示成：

```text
复合语句 CompoundStatementNode
  ├─ 赋值语句 x := 1
  └─ 扩充赋值语句 x += a
```

对应代码：

```text
parser/ast/*
Parser.java
```

### 2.3 符号表是什么

符号表就是“变量和常量名单”。

比如：

```pl0
const a = 10;
var x, i;
```

符号表里会记录：

```text
CONST a = 10
VAR x
VAR i
```

语义分析会用符号表检查：

```text
变量有没有声明
有没有重复声明
常量有没有被赋值
for 循环变量是否合法
```

对应代码：

```text
Symbol.java
SymbolType.java
SymbolTable.java
SemanticAnalyzer.java
```

### 2.4 四元式是什么

四元式是一种中间代码，格式是：

```text
(operator, arg1, arg2, result)
```

比如：

```pl0
x := 1;
x += a;
```

可以生成：

```text
(:=, 1, _, x)
(+, x, a, x)
```

人话理解：

```text
四元式就是把高级语言语句拆成更简单、更接近执行步骤的指令。
```

对应代码：

```text
Quadruple.java
IntermediateCodeGenerator.java
```

## 5. Web 主流程怎么看

最重要的入口是：

```text
CompileController.java
```

核心接口：

```text
POST /api/compile
```

前端页面点击“运行分析”后，会调用这个接口。

`CompileController` 做的事情：

```text
1. 接收前端传来的 source 源代码
2. new Lexer(source)，执行 tokenize()
3. new Parser(tokens)，执行 parse()
4. new SemanticAnalyzer().analyze(program)
5. 如果没有语义错误，就生成四元式
6. 把 tokens、astSummary、symbols、semanticErrors、quadruples 返回给前端
```

代码流程对应：

```java
Lexer lexer = new Lexer(source);
List<Token> tokens = lexer.tokenize();

Parser parser = new Parser(tokens);
ProgramNode program = parser.parse();

SemanticAnalysisResult semanticResult = new SemanticAnalyzer().analyze(program);

IntermediateCodeResult irResult = new IntermediateCodeGenerator().generate(program);
```

这就是整个项目的主线。

## 6. 用一个例子贯穿全流程

示例程序：

```pl0
const a = 10;
var x, i;
begin
  x := 1;
  x += a;
  for i := 1 to 3 do
    x += i;
end.
```

### 6.1 第一步：词法分析

Lexer 会把源代码切成 Token。

部分 Token 类似：

```text
CONST const
IDENTIFIER a
EQUAL =
NUMBER 10
SEMICOLON ;
VAR var
IDENTIFIER x
COMMA ,
IDENTIFIER i
SEMICOLON ;
BEGIN begin
IDENTIFIER x
ASSIGN :=
NUMBER 1
SEMICOLON ;
IDENTIFIER x
PLUS_ASSIGN +=
IDENTIFIER a
SEMICOLON ;
FOR for
IDENTIFIER i
ASSIGN :=
NUMBER 1
TO to
NUMBER 3
DO do
IDENTIFIER x
PLUS_ASSIGN +=
IDENTIFIER i
SEMICOLON ;
END end
PERIOD .
EOF
```

这里最关键的是：

```text
+= 被识别成 PLUS_ASSIGN
for 被识别成 FOR
to 被识别成 TO
do 被识别成 DO
```

说明 PL0 扩充词法已经生效。

### 6.2 第二步：语法分析

Parser 会根据 Token 判断程序结构。

这个例子的 AST 大概是：

```text
ProgramNode
└─ BlockNode
   ├─ ConstDeclarationNode(a = 10)
   ├─ VarDeclarationNode(x)
   ├─ VarDeclarationNode(i)
   └─ CompoundStatementNode
      ├─ AssignmentStatementNode(x := 1)
      ├─ AssignmentStatementNode(x += a)
      └─ ForStatementNode(i, 1, 3)
         └─ AssignmentStatementNode(x += i)
```

人话解释：

```text
Parser 不执行代码。
它只是确认这些 Token 能组成合法程序，并把结构保存成 AST。
```

### 6.3 第三步：语义分析

SemanticAnalyzer 会检查语义问题。

这个例子会得到符号表：

```text
CONST a = 10
VAR x
VAR i
```

它会检查：

```text
x 已声明，可以赋值
a 已声明，可以参与表达式
i 已声明，可以作为 for 循环变量
x += i 中 x 和 i 都已声明
```

所以语义错误为空：

```text
无语义错误
```

如果输入：

```pl0
begin
  x += 1;
end.
```

语义分析会报：

```text
变量未声明: x
```

如果输入：

```pl0
const a = 1;
begin
  a := 2;
end.
```

语义分析会报：

```text
常量不能被赋值: a
```

### 6.4 第四步：四元式生成

没有语义错误时，才生成四元式。

示例程序可能生成类似：

```text
(:=, 1, _, x)
(+, x, a, x)
(:=, 1, _, i)
(label, _, _, L1)
(j>, i, 3, L2)
(+, x, i, x)
(+, i, 1, i)
(j, _, _, L1)
(label, _, _, L2)
```

解释：

```text
(:=, 1, _, x)      把 1 赋值给 x
(+, x, a, x)       对应 x += a
(:=, 1, _, i)      for 循环变量 i 从 1 开始
(label, _, _, L1)  循环开始标签
(j>, i, 3, L2)     如果 i > 3，跳到循环结束
(+, x, i, x)       循环体：x += i
(+, i, 1, i)       循环变量 i 自增
(j, _, _, L1)      跳回循环开始
(label, _, _, L2)  循环结束标签
```

## 7. Lexer 模块怎么看

包：

```text
com.pengy.pl0.lexer
```

核心文件：

```text
TokenType.java
Token.java
Lexer.java
```

### 7.1 TokenType

定义所有词法类型。

比如：

```text
IDENTIFIER
NUMBER
CONST
VAR
BEGIN
END
FOR
TO
PLUS_ASSIGN
MINUS_ASSIGN
INCREMENT
DECREMENT
ASSIGN
EOF
```

### 7.2 Token

表示一个词法单元。

字段：

```text
type：类型
lexeme：原文
line：行号
column：列号
```

### 7.3 Lexer

`Lexer` 负责扫描源代码。

主要方法：

```text
tokenize()
readIdentifierOrKeyword()
readNumber()
readSymbol()
```

`readSymbol()` 里处理扩充符号：

```text
+=
-=
+ 
--
```

如果遇到不认识的字符，会抛出词法错误。

## 8. Parser 模块怎么看

包：

```text
com.pengy.pl0.parser
```

核心文件：

```text
Parser.java
ParserException.java
parser/ast/*.java
```

### 8.1 Parser 是递归下降分析器

递归下降就是：

```text
每一种语法结构，用一个 Java 方法来解析。
```

比如：

```text
parseBlock()       解析程序块
parseStatement()   解析语句
parseExpression()  解析表达式
parseTerm()        解析乘除
parseFactor()      解析数字、变量、括号
```

### 8.2 为什么用递归下降

因为 PL0 语法比较小，用递归下降写起来直观：

```text
看到 const 就解析常量声明
看到 var 就解析变量声明
看到 begin 就解析复合语句
看到 for 就解析 for 语句
看到标识符就解析赋值、自增、自减语句
```

答辩时可以说：

```text
本项目采用递归下降分析方法，将不同语法结构映射为不同解析函数，代码结构和文法结构对应清晰，适合 PL0 这种小型语言。
```

## 9. AST 节点怎么看

包：

```text
com.pengy.pl0.parser.ast
```

重要节点：

```text
ProgramNode：整个程序
BlockNode：声明 + 主语句
ConstDeclarationNode：常量声明
VarDeclarationNode：变量声明
CompoundStatementNode：begin ... end
AssignmentStatementNode：赋值、+=、-=
UnaryStatementNode：++、--
ForStatementNode：for 循环
NumberExpressionNode：数字表达式
IdentifierExpressionNode：变量表达式
BinaryExpressionNode：二元表达式，如 a + b
```

AST 是 Parser 的输出，也是 Semantic 和 IR 的输入。

## 10. Semantic 模块怎么看

包：

```text
com.pengy.pl0.semantic
```

核心文件：

```text
Symbol.java
SymbolType.java
SymbolTable.java
SemanticError.java
SemanticAnalysisResult.java
SemanticAnalyzer.java
```

### 10.1 Symbol 和 SymbolTable

`Symbol` 表示一个符号：

```text
名字：a / x / i
类型：CONST / VAR
值：常量有值，变量没有固定值
```

`SymbolTable` 保存所有声明过的变量和常量。

### 10.2 SemanticAnalyzer 做什么

主要检查：

```text
重复声明
未声明变量
常量不能赋值
常量不能自增自减
for 循环变量必须声明
for 循环变量不能是常量
表达式里的变量必须声明
```

它的输入是 AST，输出是：

```text
符号表
语义错误列表
```

## 11. IR 模块怎么看

包：

```text
com.pengy.pl0.ir
```

核心文件：

```text
Quadruple.java
IntermediateCodeResult.java
IntermediateCodeGenerator.java
```

### 11.1 Quadruple

四元式对象，字段：

```text
operator
arg1
arg2
result
```

### 11.2 IntermediateCodeGenerator

负责把 AST 转成四元式。

支持：

```text
x := 1
x += 2
x -= 3
x++
x--
for i := 1 to 10 do ...
表达式 a + b、a * b
```

如果表达式比较复杂，会生成临时变量：

```text
t1
t2
```

如果是 for 循环，会生成标签：

```text
L1
L2
```

## 14. 答辩时怎么讲

可以按这个顺序讲：

### 14.1 先讲项目目标

```text
本项目以 PL0 语言为基础，实现了 PL0 的扩充编译器前端。
扩充内容包括 +=、-=、++、-- 和 for 语句。
```

### 14.2 再讲总体流程

```text
源码输入后，先进行词法分析，得到 Token 序列；
再进行语法分析，生成 AST；
然后进行语义分析，生成符号表并检查语义错误；
最后在无语义错误的情况下生成四元式。
```

### 14.3 讲自己负责的部分

你是韩炼，负责：

```text
语法分析
语义分析
```

可以这样讲：

```text
语法分析部分采用递归下降方法，不同语法结构对应不同解析函数，如 parseStatement、parseExpression、parseForStatement 等。
语义分析部分通过符号表记录变量和常量声明，并检查重复声明、未声明变量、常量赋值、for 循环变量合法性等问题。
```

### 14.4 讲如何证明能跑

```text
项目提供 Web 页面，可以输入 PL0 程序并展示 Token、AST、符号表、错误和四元式。
同时项目编写了 JUnit 测试，覆盖词法、语法、语义和中间代码生成。
```

### 14.5 讲一个例子

可以用这个例子：

```pl0
const a = 10;
var x, i;
begin
  x := 1;
  x += a;
  for i := 1 to 3 do
    x += i;
end.
```

讲它：

```text
词法阶段识别 const、var、+=、for、to、do；
语法阶段生成 ProgramNode、BlockNode、CompoundStatementNode 和 ForStatementNode；
语义阶段生成 a、x、i 的符号表并确认无错误；
中间代码阶段生成赋值、加法、标签和跳转四元式。
```

## 15. 当前项目不足和可改进点

这个项目已经能完成课程设计演示，但还有可以改进的地方：

```text
1. AST 目前在页面上只展示概要，没有完整树形可视化。
2. 语法支持的是课程设计需要的 PL0 核心子集，不是完整 Pascal。
3. 错误处理以抛异常和收集错误为主，还没有复杂的错误恢复机制。
4. Web 页面偏课程设计演示型，还可以继续美化。
5. 四元式生成覆盖了核心语句，但没有做优化。
6. 没有实现目标代码生成或解释执行。
```

答辩时如果老师问不足，可以这样回答：

```text
本项目重点完成编译前端流程和 PL0 扩充语法验证，因此主要实现词法、语法、语义和中间代码生成。后续可以继续完善 AST 可视化、错误恢复和中间代码优化。
```

## 16. 一句话总结

这个项目的主线就是：

```text
源码 → Token → AST → 符号表/语义错误 → 四元式 → Web 展示
```

你只要能把这条线讲清楚，就已经能讲懂这个项目了。
